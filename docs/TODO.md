# CMS 当前开发路线图

**最后更新**: 2026-03-25

本文件只描述当前有效的开发计划。历史执行记录和旧阶段说明已归档到 [`docs/archive/TODO_HISTORY.md`](./archive/TODO_HISTORY.md)。

## 当前判断

当前仓库已经完成基础基线收敛：

- 应用边界已稳定：`web-frontend` / `web-admin` / `api`
- 启动脚本、环境变量、文档入口已经对齐
- 后台请求链路已统一到 `api-v1`
- 多租户和鉴权主链路已可运行

当前工作的重点不应再是“继续做大范围重构”，而应转向：

1. 稳定主链路
2. 补齐回归测试
3. 完成后台内容管理闭环
4. 完成前台可交付能力

## P0：稳定性收口

这些任务优先级最高，必须先做。

- [ ] 为鉴权、refresh token、租户切换、dashboard 统计补齐集成测试
- [ ] 跑通并固定 `pnpm dev` / `pnpm build` / `pnpm typecheck` / `pnpm test` 主链路
- [ ] 统一后台所有上传、列表、详情、删除操作的错误处理和登录失效跳转
- [ ] 复查 API 中依赖 `tenantId` 的接口，避免再出现 token 字段缺失导致的 400/401
- [ ] 清理 remaining console/debug 输出，只保留必要日志

## P1：后台核心闭环

目标是让后台达到“可持续录入和管理内容”的状态。

- [ ] 文章创建、编辑、删除、发布全链路验收
- [ ] 分类、标签、媒体管理页面补齐交互缺口
- [ ] 用户管理、租户管理、设置页梳理成明确可用/不可用状态
- [ ] 富文本编辑器与媒体库联动走查
- [ ] 后台权限边界复查：未授权页面和按钮是否正确限制

## P2：前台可交付化

目标是让前台站点形成完整的浏览和发现体验。

- [ ] 首页、文章详情、分类页、标签页、搜索页做一次端到端验收
- [ ] SEO 基础项：metadata、Open Graph、sitemap、robots
- [ ] 前台内容列表和详情页的空状态、错误状态、加载状态统一
- [ ] 多租户场景下验证前台内容隔离是否正确

## P3：工程化与质量保障

这部分在主链路稳定后推进，不提前堆功能。

- [ ] 为 API 高风险路由补齐集成测试
- [ ] 为后台登录、文章管理、租户切换增加最小 E2E 覆盖
- [ ] 将当前真实可运行的检查接入 CI
- [ ] 补齐数据库迁移、seed、环境变量的开发者说明

## 暂缓项

这些方向不是不要做，而是当前不该排在前面。

- [ ] Prometheus / Grafana / 重监控体系
- [ ] 复杂缓存分层优化
- [ ] 大规模 CI/CD 流水线设计
- [ ] GraphQL API
- [ ] 插件系统
- [ ] 多语言

## 近期建议执行顺序

### 第一步

- 补鉴权 / 租户 / dashboard 回归测试
- 固定 API 与后台主链路

### 第二步

- 完成后台内容管理闭环
- 明确设置页、用户页、租户页哪些能力是正式可用的

### 第三步

- 做前台完整验收
- 补 SEO 基础项

### 第四步

- 再做缓存、监控、CI 等工程化增强

## 完成标准

- 任何进入 `P0` 的任务，必须同时满足“代码可运行、测试可验证、文档已同步”
- 新增功能默认附带最少一条验证路径
- 文档以当前代码事实为准，不再保留与现状冲突的计划描述
