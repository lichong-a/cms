# CMS 当前开发路线图

**最后更新**: 2026-03-29

本文件描述当前有效的开发计划，并以当前代码事实和已验证链路为准。历史阶段说明已归档到 [`docs/archive/TODO_HISTORY.md`](./archive/TODO_HISTORY.md)。

## 当前状态

截至 2026-03-29，仓库已经完成基础基线收敛，并且主工程链路已验证：

- 应用边界已稳定：`web-frontend` / `web-admin` / `api`
- 后台请求链路已统一到 `api-v1`
- 多租户与鉴权主链路已具备可运行基础
- 当前工作区干净，无未提交改动
- `pnpm test` 已通过
- `pnpm build` 已通过

当前阶段不再是“大范围重构”，而是进入交付前的收口阶段：

1. 稳定主链路
2. 补齐真实回归测试
3. 完成后台内容管理闭环
4. 完成前台可交付能力

## 当前风险判断

以下问题已经暴露，必须优先处理：

- [ ] E2E 仍保留“占位页 / 模拟认证”假设，未覆盖真实登录与租户切换链路
- [ ] 子项目 README 与当前代码事实存在漂移，容易误导后续开发
- [ ] 仓库中仍有一批调试输出和临时脚本，需要分级清理

## P0：稳定性收口

这些任务优先级最高，必须先做。

- [ ] 统一后台认证方案，明确 access token / refresh token / 页面保护 / 登录失效跳转的单一实现
- [ ] 为鉴权、refresh token、租户切换、dashboard 统计补齐集成测试
- [ ] 跑通并固定 `pnpm dev` / `pnpm build` / `pnpm typecheck` / `pnpm test` 主链路
- [ ] 统一前台、后台、存储相关模块的 API base URL 读取方式，去掉旧端口和局域网地址硬编码
- [ ] 统一后台上传、列表、详情、删除操作的错误处理和登录失效跳转
- [ ] 复查 API 中依赖 `tenantId` 的接口，避免再次出现 token 字段缺失导致的 400/401
- [ ] 清理 remaining console/debug 输出，只保留必要日志
- [ ] 同步修正文档，确保 README、环境变量示例、当前实现一致

## P1：后台核心闭环

目标是让后台达到“可持续录入和管理内容”的状态。

- [ ] 文章创建、编辑、删除、发布全链路验收
- [ ] 分类、标签、媒体管理页面补齐交互缺口
- [ ] 用户管理、租户管理、设置页梳理成明确可用/不可用状态
- [ ] 富文本编辑器与媒体库联动走查
- [ ] 后台权限边界复查：未授权页面和按钮是否正确限制
- [ ] 后台页面中的错误提示、空状态、成功反馈统一

## P2：前台可交付化

目标是让前台站点形成完整的浏览和发现体验。

- [ ] 首页、文章详情、分类页、标签页、搜索页做一次端到端验收
- [ ] SEO 基础项：metadata、Open Graph、sitemap、robots
- [ ] 前台内容列表和详情页的空状态、错误状态、加载状态统一
- [ ] 多租户场景下验证前台内容隔离是否正确
- [ ] 清理前台 API 请求实现中的旧路径和重复封装

## P3：工程化与质量保障

这部分在主链路稳定后推进，不提前堆功能。

- [ ] 为 API 高风险路由补齐集成测试
- [ ] 为后台登录、文章管理、租户切换增加最小 E2E 覆盖
- [ ] 将当前真实可运行的检查接入 CI
- [ ] 补齐数据库迁移、seed、环境变量的开发者说明
- [ ] 建立“新增功能至少附带一条验证路径”的提交约束

## 暂缓项

这些方向不是不要做，而是当前不该排在前面。

- [ ] Prometheus / Grafana / 重监控体系
- [ ] 复杂缓存分层优化
- [ ] 大规模 CI/CD 流水线设计
- [ ] GraphQL API
- [ ] 插件系统
- [ ] 多语言

## 四周执行计划

### 第 1 周：主链路收口

- [x] 统一后台认证实现，消除 `localStorage` 与 cookie 双轨行为
- [x] 修正前台、后台和存储模块中的 API 地址硬编码
- [ ] 补齐 auth / refresh token / dashboard / tenant switch 的测试缺口
- [x] 修正 README、`.env.example`、子项目说明中的漂移项

本周退出标准：

- `pnpm test`、`pnpm build`、`pnpm typecheck` 可稳定通过
- 管理后台在开发和生产语义下都能正确完成登录、失效、跳转
- 仓库中不再残留局域网 API 地址

当前阻塞：

- [ ] `pnpm typecheck` 仍被仓库既有的 Prisma 脚本、Playwright 配置、根级 TS 配置问题阻塞

### 第 2 周：后台闭环验收

- [ ] 逐项走通文章创建、编辑、删除、发布
- [ ] 补齐分类、标签、媒体页面缺口
- [ ] 明确设置页、用户页、租户页哪些能力正式可用
- [ ] 统一后台反馈提示、错误提示、空状态

本周退出标准：

- 后台可连续完成内容录入、管理、发布
- 关键管理页没有“点了没反应”或“失败但无提示”的链路
- 可用与不可用能力有明确 UI 状态或文档说明

### 第 3 周：前台交付验收

- [ ] 首页、详情、分类、标签、搜索页做全链路验收
- [ ] 统一前台加载态、空状态、错误态
- [ ] 补齐基础 SEO 产物和 metadata
- [ ] 验证多租户下的前台内容隔离

本周退出标准：

- 前台主要浏览路径可完整演示
- 无明显错误页、空白页、错误 fallback 漏洞
- SEO 基础项达到最小可交付水平

### 第 4 周：质量固化

- [ ] 增加最小 E2E：后台登录、文章管理、租户切换
- [ ] 为高风险 API 路由继续补集成测试
- [ ] 接入 CI 中的真实检查
- [ ] 补齐迁移、seed、环境变量、运行说明

本周退出标准：

- 核心主链路变更可被自动检查拦住
- 新同事可按文档完成本地启动与基础验证
- 当前阶段的交付边界清晰、风险可控

## 近期执行顺序

1. 先收口认证、租户、dashboard、API 地址与文档漂移问题
2. 再完成后台内容管理闭环和管理侧状态统一
3. 然后做前台完整验收与 SEO 基础项
4. 最后再推进 CI、迁移说明、工程化补强

## 完成标准

- 任何进入 `P0` 的任务，必须同时满足“代码可运行、测试可验证、文档已同步”
- 新增功能默认附带最少一条验证路径
- 文档以当前代码事实为准，不再保留与现状冲突的计划描述
- 每周结束时都需要更新本文件中的完成项和下一周阻塞项
